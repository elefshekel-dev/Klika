# רסיסים

מחברת רסיסים ספרותית — כלי מקומי (local-first) ללכידה מהירה של טקסטים קצרים:
שורה שעלתה בראש, בית, פסקה, רעיון. עובד אופליין לחלוטין, מותקן כאפליקציה (PWA),
וגיבוי אופציונלי ל-Google Drive.

הכתיבה בעברית — RTL מלא. אין backend, אין הרשמה, אין ענן חובה. הכל נשמר במכשיר.

## הפעלה מקומית

דרוש Node.js 20+.

```bash
npm install
npm run dev
```

האפליקציה תעלה בכתובת שתופיע בטרמינל (בדרך כלל <http://localhost:5173>).

## בנייה

```bash
npm run build      # בונה ל-dist/
npm run preview    # תצוגה מקדימה של הבנייה
```

## פריסה (deploy)

זו אפליקציה **סטטית** — התוצר ב-`dist/` הוא קבצים סטטיים בלבד. אפשר לארח בכל
שירות לאתרים סטטיים (Netlify, Vercel, Cloudflare Pages, GitHub Pages וכו').

- **Netlify / Vercel**: פקודת build היא `npm run build`, תיקיית הפרסום היא `dist`.
- חשוב: הגדירו הפניה (rewrite) של כל הנתיבים ל-`index.html` (SPA fallback), כדי
  שניווט ישיר לנתיב פנימי יעבוד.
  - Netlify: קובץ `public/_redirects` עם השורה `/* /index.html 200`.
  - Vercel: `rewrites` ב-`vercel.json` מ-`/(.*)` ל-`/`.

## גיבוי ל-Google Drive (אופציונלי)

בלי הגדרה — האפליקציה עובדת במלואה, רק בלי גיבוי לענן. הכל נשמר במכשיר.
הגיבוי הוא שכבה שמתווספת מעל, לא תלות.

מה נשמר בגיבוי: תיקייה **גלויה** בשם "רסיסים" ב-Google Drive שלך, ובתוכה:
- `fragments-data.json` — כל הנתונים (זה הקובץ שממנו משחזרים ושמסנכרנים).
- תיקיית `fragments/` — קובץ `.md` נפרד לכל רסיס, בשם `YYYY-MM-DD-<שורה-ראשונה>.md`.
- תיקיית `collections/` — קובץ `.md` מאוחד לכל אסופה.

התיקייה גלויה בכוונה — כך יש לך גישה לגיבויים גם בלי האפליקציה.

### יצירת מזהה OAuth ב-Google Cloud Console — שלב אחר שלב

ההסבר הזה מיועד גם למי שלא מפתחת. זה חינמי ולוקח כמה דקות. צריך לעשות את זה
פעם אחת.

1. **פותחים את הקונסולה.** נכנסים ל-<https://console.cloud.google.com> עם חשבון
   Google, ומאשרים את תנאי השימוש אם מבקשים.
2. **יוצרים פרויקט.** למעלה, ליד הלוגו, לוחצים על בורר הפרויקטים ואז
   "New Project" / "פרויקט חדש". נותנים שם (למשל "רסיסים"), יוצרים, ובוחרים
   את הפרויקט החדש.
3. **מפעילים את Drive API.** בתפריט (☰) → "APIs & Services" → "Library".
   מחפשים "Google Drive API", נכנסים, ולוחצים "Enable" / "הפעלה".
4. **מגדירים מסך הסכמה (OAuth consent screen).** בתפריט → "APIs & Services" →
   "OAuth consent screen". בוחרים "External" / "חיצוני" ולוחצים "Create".
   - ממלאים שם אפליקציה (למשל "רסיסים"), אימייל תמיכה, ואימייל יצירת קשר בסוף.
   - שומרים וממשיכים דרך המסכים (אפשר לדלג על Scopes ו-Test users, או להוסיף
     את כתובת האימייל שלך תחת "Test users" כדי לאשר גישה בזמן שהאפליקציה
     במצב בדיקה).
5. **יוצרים את המזהה (Client ID).** בתפריט → "APIs & Services" → "Credentials"
   → "Create Credentials" → "OAuth client ID".
   - "Application type": בוחרים **"Web application"**.
   - תחת **"Authorized JavaScript origins"** מוסיפים את הכתובות שמהן תיפתח
     האפליקציה. חשוב — בלי נתיב בסוף, רק הדומיין:
     - לפיתוח מקומי: `http://localhost:5173`
     - לפריסה: כתובת האתר שלך, למשל `https://resisim.example.com`
   - לא חייבים "Authorized redirect URIs" (השיטה כאן לא משתמשת בהפניה).
   - לוחצים "Create". נפתח חלון עם **Client ID** — מעתיקים אותו.
6. **מכניסים את המזהה לאפליקציה.** יוצרים קובץ `.env` (או `.env.local`) בשורש
   הפרויקט, לפי `.env.example`, ומדביקים:

   ```
   VITE_GOOGLE_CLIENT_ID=המזהה-שהעתקת.apps.googleusercontent.com
   ```

   בונים מחדש (`npm run build`) או מפעילים מחדש את `npm run dev`. עכשיו, במסך
   ההגדרות באפליקציה, יופיע כפתור "חיבור ל-Google Drive".

הערות:
- ה-scope היחיד שמתבקש הוא `drive.file` — האפליקציה רואה ויכולה לגעת רק
  בקבצים שהיא עצמה יצרה, לא בשאר ה-Drive שלך.
- המזהה נטען ממשתנה הסביבה בלבד, לא מוטמע בקוד.
- קונפליקט בין מכשירים נפתר בלי לדרוס: הגרסה החדשה נשמרת, והגרסה השנייה
  נשמרת כרסיס עותק (עם הכיתוב "עותק מסנכרון") כדי ששום דבר לא יאבד.
